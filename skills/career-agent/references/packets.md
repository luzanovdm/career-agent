# Application packets

A complete packet requires a reviewed career-source extraction ledger, captured achievement inventory and a current semantic adaptation review of the actual resume. Perform the [achievement workflow](achievement-adaptation.md) even when no inventory exists yet. Save incomplete drafts with explicit conditional status; missing answers or review never prohibit saving. Numeric/structural audit success alone is not proof of semantic quality.

Follow [evidence-preserving achievement adaptation](achievement-adaptation.md): retain original claims/metrics, interpret contribution and significance before selection, reuse grouped clarification answers, and audit the actual draft, retained secondary strengths and specifically justified exclusions before saving a resume.

Use [the interaction contract](interaction.md) for every intake choice, factual clarification or preference: native questionnaires are required when applicable in the current host/mode; keep conclusions in chat and avoid duplicate prose questions.
Prepare for each suitable new exact case selected by the authorized search scope; finding cases includes packet preparation by default under [the search completion contract](search-cases.md). A standalone packet request still targets its selected exact opportunity. Recheck current source evidence where browsing is authorized. If it is unavailable, label the packet's status unverified and preserve unresolved checks. Read the confirmed fact bank and disclosure restrictions before drafting.

## Packet contents

1. Tailored resume using supported, permitted accomplishments; choose its language for the role with the user. Never silently convert side projects into employment, team outcomes into personal results, aspirations into qualifications or overlapping dates into extra years.
2. Concise cover letter connecting supported work to the employer's product needs. Use confident, specific language. Do not open with apologies, deficiencies, “although I lack” or requests for another role. Keep material gaps in the private assessment; answer direct employer questions honestly.
3. Form-field inventory from the actual observed form: exact label, type, choices, requiredness, help/consent text, limits, source and observation date. Never present guessed fields as observed. Without form access, provide a clearly labeled provisional checklist. Do not create accounts or accept terms to inspect a form.
4. Proposed answers, reusable cache references and new unresolved questions. A mandatory salary field does not authorize disclosure of the private floor. Ask for or reuse the user-approved desired answer with its exact currency, gross/net and period.
5. Private source-backed fit assessment and unresolved items, including critical eligibility, unknown freshness, noncritical gaps and disclosure concerns.

All new resume, cover, dossier and form-answer drafts are .md only. Do not generate per-vacancy TXT/PDF/DOCX; render upload formats only for an actual required upload or explicit user request. Inspect final Markdown links and actual URL fields; private local paths are not public resume URLs.

Store general reusable resumes once in the central private material library. Reuse an unchanged version/hash without generating another PDF. Create a new immutable version only for a real content/format change, and defer PDF generation until a reviewed deliverable or form needs it. Organize Applications by company, exact vacancy and distinct application attempt with readable names plus stable IDs. Each attempt pins chosen immutable material versions/hashes using relative symlinks or portable reference files; never a moving “latest” CV. Keep letters, observed answers, evidence and correspondence scoped to the attempt; share vacancy research/interview context at vacancy level. See [material storage](materials.md).

Version every packet. Track role ID, version, artifact paths or export names, language, supporting fact IDs, source observations, review status and creation date. Preparation is never a sent event. External claims require undisputed confirmed facts with disclosure permission; private assessments may reference confidential evidence without publishing it. New contradictions flag existing materials for review and block new unsupported external claims; a model-generated suggestion is insufficient evidence. Private assessment may discuss hypotheses but cannot label them confirmed.

## Answer cache

A cache key is semantic meaning + structured scope + units. Store value, user confirmation date/evidence, validity start/end and sensitivity. Examples of distinct meanings: `compensation.goal` versus `compensation.floor`; `work_authorization` per jurisdiction; `availability.notice_period` in days. Scope can include company ID, opportunity ID, jurisdiction, contract type, purpose and language. Require exact scope matching by default; ask before broadening it. Units include currency, gross/net and period for money. Do not reuse USD annual gross as EUR monthly net, or a historic answer as current.

Use stable semantic IDs rather than fuzzy label similarity. If no valid confirmed exact match exists, ask with a ready-made proposed answer. For reusable facts, confirm once and reuse within validity; do not keep asking unchanged questions. Mark `unknown`, `no_metric` and `confidential` explicitly when relevant.

Employer-specific privacy, retention, sharing and legal agreement consents must never transfer between employers, roles or revised consent text. Cache only the user's decision for the exact employer, role, observed consent-text version and purpose; always present the current agreement for a fresh explicit choice. The optional helper returns no reusable consent answer at all. Preparing an answer does not accept the agreement.

## Handoff to the user

Show the packet, exact form answers and unresolved checks for review. Stop before submission. This version implements no automated send. If the user submits manually, record a separate attempt only from evidence or the user's explicit report, retaining uncertainty where applicable. An uncertain submit is a blocker to retry: reconcile receipt/history first, never blindly resubmit.

Relevance changes order, emphasis and detail; preserve secondary meaningful accomplishments and supported metrics concisely. Do not drop them through a role template, arbitrary length cutoff or blanket unselected-to-irrelevant mapping. Explain primary achievements more deeply. Mark conditional/failed drafts clearly in the private handoff; audit readiness is not semantic/editorial approval.
