# Contacts, opportunities and selected packets

Resolve the actual task/count unit, selected tracks, eligibility criterion and budget. Contacts count distinct qualified people; ordinary search counts new exact cases. Retain the original job-search scope when work is partial; preliminary research/contact batches do not replace its packet completion. Resolve material track conditions and contribution questions through the intake contract, reusing current answers. Authorized preliminary findings and conditional drafts can be saved while answers wait. Reconcile exact history and unresolved actions first. Check research-check before each authorized lookup; reuse unchanged durable scope, stop immediately on pause and do not guess endpoints.

Find a useful evidenced person through employer/team/role/professional context. Identity, current affiliation, purpose-specific relevance and route provenance are separate axes. A current official page may suffice without a universal date/source-count rule. Unknown/conflicting affiliation stays a lead and does not count as current. A profile URL is a usable professional route; neither a published email nor a profile establishes delivery, a warm relationship or willingness to refer. No sender/MIME/test account is needed for channel-neutral drafts.

Capture readable source observations, company identity and contact.capture. Source assessments use source_id, axes identity/affiliation/relevance and assessment supports/conflicts/unknown. Route contains kind,value,source_id. Company identity uses an evidenced domain/key, never a name-only merge. Exact opportunities use company-scoped requisitions or canonical role URLs. REQ-42 at different employers is distinct; a note mentioning an ID is not identity. A speculative company need stays speculative. case.capture stores track rationales and route; ordinary form is secondary and needs the actual contact-search gap, not an invented referral.

For contacts-only, save selected people/evidence/route/next action and requested contact/message view. Do not require resumes, email diagnostics or full application packets.

For normal job search, create packet.create for the exact case/person/purpose, then packet.save with tailored resume, person/company-specific message, private dossier and concise interview material. Only a selected form route requires answers. Explicit research-only saves cases/evidence/fit/unknowns without claiming packets complete. Several drafts can exist; packet.primary explicitly coordinates the case's route. packet.select changes a selected immutable version; registering alternatives never changes it.

Before review, read source → supported claim meaning → actual external wording. Preserve meaningful supported metrics and secondary achievements with coverage included/condensed/private/excluded/pending; exclusions need concrete reason/provenance. Review actual claim spans, numbers/units, attribution, dates, recipient rationale, current phone/disclosure and unsupported additions. Tone is confident, concrete, natural and appropriate to the chosen channel; no invented familiarity, praise, motives, guarantees or apologetic self-rejection. External resumes state confirmed personal contributions and team results confidently; internal caveats about an unmeasurable individual causal share stay private unless their omission would mislead. Numeric checks bind each occurrence to its mapped claim or scoped answer, not an equal digit elsewhere. Canonical company/name/domain references are automatic. For a source-backed technology/product identifier, the agent supplies review.entity_refs [{text,source_id}] once; scripts resolve exact occurrences and preserve dependencies. Do not ask the user to mark ordinary brands or remove their digits for a green result. Ambiguous identifiers support an exact entity_spans binding; scalar external answers use answer_spans. Use schema packet.save for bounded shapes and Unicode-code-point offsets. Store findings, tone_findings, limitations, exact claim_spans and coverage; an unreviewed UI edit intentionally omits review and stays a draft.

Save all text slots in a replacement packet version, used_claim_ids and relevant answer_ids; source_version_id preserves lineage. Deliver reads the exact selected saved bytes and current assessment. A converted DOCX/PDF attaches only with an actual byte-bound extraction receipt against its selected source, including hidden/header/footer contact data. Use stage then artifact.attach; unavailable PDF extraction is explicit, never replaced by declared text. Keep private dossier/interview/notes out of employer handoffs.

For ordinary job search, keep the original scope in batch.save with task:"job_search", count_unit:"cases". Preliminary research/contact/packet batches link through parent_id. Use query assess for root or child: scope_complete describes that batch, while task_complete and remaining_work describe the original job-search goal. deliver returns selected IDs/hashes and task_progress; render produces requested views. assessment.prepared describes saved reviewed text; conditional, eligibility and unknown_details retain unresolved conditions separately. Report those results rather than closing the task from a smaller successful batch. A referral packet needs no imaginary form; a form fallback cannot complete a people quota. Preparation never authorizes sending.


Use context --task packets --case-id CASE --track-id TRACK and follow next_cursor while partial pages remain. Pagination reports total/remaining/omitted_by_scope; do not treat the first 25 claims as the complete bank. Read an exact source_id, claim_id or answer_id when needed. Scoped answers expose reusable_here; a response for another track/company/case or unresolved scope is not reusable here. A URL-only unreadable page does not support ready status; record actual readable supplied confirmation separately with honest provenance.

An initial resume audit accounts for the meaningful claim bank. Later target reviews may reference base_coverage_version_id and store only explicit coverage changes. Included/condensed dispositions still require used_claim_ids and exact current resume spans with original numerical tokens and recognized units. The mechanical validator catches missing spans/metrics, not semantic equivalence, ownership truth or tone quality. Report those review limits and investigate unsupported qualitative additions yourself.

A batch is an immutable request contract: task, requested_count, count_unit, track_ids, criterion label, required_outputs and optional typed predicate. Use schema batch.save; a human criterion string is not an executable rule. predicate.kind matches qualified_people, evidenced_cases (research) or prepared_cases; essential_policy is no_confirmed_failure or verified_pass. Wrong-track items remain saved but receive no qualifying quota credit. Changing scope/quota/criterion requires a separate batch. A useful person also needs evidenced relevance to the requested track, through linked case rationale or contact track_rationales.

An existing case ID cannot be retargeted to a different exact opportunity. Save a distinct role or resolve identity explicitly; do not rewrite URLs to preserve old prepared status. Meaningful same-role metadata changes invalidate the old review, while unrelated private notes do not. On MATERIAL_CHANGED stop selected delivery and restore exact original bytes or create/review a new version; never reconstruct old sent bytes from memory.
