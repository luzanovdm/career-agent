# Integrated outreach design

This is a local, capability-aware personal workflow, portable without a hosted backend or paid service. Research and external actions retain their separate permissions. The bundled helpers inspect and record; they never research, send, purchase or schedule.

## Evidence to action

Keep outreach mode (vacancy application, speculative company/problem opportunity, paid project/contract) separate from message purpose (application, cold referral/introduction, purposeful follow-up). Preserve the chain: source evidence → role/company problem → relevant contact rationale → supported message → exact selected payload.

Find the most relevant evidenced owner: vacancy author, recruiter or hiring manager for a role; engineering/product owner or CTO for an appropriately small company/project. This is a relevance decision, not an exhaustive search or a seniority ranking. Stop once a sufficiently qualified usable route exists; missing perfect contacts must not indefinitely prevent an ordinary application.

Use vacancy sources, official team pages, professional profiles, engineering posts and talks, then published professional contact or authorized prior correspondence. Optional public professional data providers are adapters, never mandatory or automatically purchased. Record independent confidence axes for identity, current affiliation, role relevance, address provenance and observed delivery. Published is not valid, DNS is not a mailbox, and delivery does not prove the recipient is the intended person. Guesses remain guesses; no address enumeration or leaked/private irrelevant contacts.

Share evidenced person/channel identity across roles; merge aliases only with evidence and keep namesakes distinct. A form application prevents duplicate reapplication but permits a separately justified, authorized personal follow-up acknowledging the form. One coordinated outreach per company/opportunity at a time; switching recipient needs documented reassignment/failure or an approved waiting policy. Honor opt-outs at their expressed person/channel/company/role scope; rejection is not automatically a permanent company ban. Preserve minimal suppression history during handoff and cleanup.

Direct applications include the CV when expected. An initial cold referral inquiry defaults to a short message without attachments/links; this is not a global prohibition. A stranger is not a warm connection and a referral draft is not a confirmed referral. Draft/ready, delivery outcome, application/conversation progress and permission are independent.

## Payload diagnostics

Inspect the actual representative outgoing MIME payload: plain/HTML parity, headers, attachment metadata, visible and actual URL destinations, hidden content, tracking and shorteners. Preserve supported accomplishments and metrics; lexical flags alone never justify deleting crypto, monetary amounts or other truthful experience. Access denial such as LinkedIn 999/403 is inconclusive, not a dead link.

Keep exact payload SHA-256 separate from the representative variant fingerprint. The variant binds declared sender/provider, delivery configuration, template, stable links and attachment generation revisions; routine candidate/vacancy text changes do not create another test obligation. The agent must compare actual structure against those declarations and advance revisions after material changes. Exact bytes bind each individual diagnostic action and its permission.

Local inspection cannot establish receiver-side SPF/DKIM/DMARC or SpamAssassin results. Those need an authorized external receiving test through a supported adapter. Keep receiver evidence, score, threshold/rules, timestamp, sender/provider, fingerprints and consent reference in the private workspace. A score is a heuristic, never an inbox probability or guarantee. Distinguish missing mailbox/domain, hard/temporary bounce, quota, actual spam rejection, accepted delivery and unknown silence.

## Cadence, permission and recovery

At session/batch start check due: before the first active email batch without a current representative test; after material variant changes; then every seven days while outbound is active (configurable). Do not retest every tailored message. Local-only mode never discloses data externally. Missing/blocked/failed diagnostics are visible warnings and leave independent research/preparation available; real authentication/systematic rejection pauses only affected delivery. Service quotas do not invalidate an employer contact.

Diagnostic permission is service/recipient/sender/provider/data/purpose bounded, with explicit one-time or standing validity and usage limits. Reuse a still-valid grant within scope without repeated prompts. A one-time grant is not standing permission; employer legal-consent rules remain unchanged. Revocation takes effect before the next dispatch. No personal grants or report addresses are distributed.

Persist durable action intent through the existing exclusive state transaction before any host-managed external action. Claims bind exact payload and use stable idempotency keys. An action handed to a provider remains dispatching/uncertain after crash or timeout until provider/history reconciliation proves its outcome; no timer permits blind retry. Provider idempotency may help but does not create an exactly-once guarantee. Check inbound immediately before follow-up; a late reply cancels that follow-up, not authorizes a new reply.

Diagnostic actions never enter application attempts, counts or follow-up triggers. Manual application sends still reconcile into the established attempts/history owner. External tests need real supported host tools; the source adds no sending path. Background work exists only with an actually supported, explicitly authorized scheduler; otherwise the next session performs the due check, with no activity while closed.

## Integration and validation

Optional additive v1 records live in canonical private state, use existing validation, revision checks, locks and backups, and appear in plain summaries without becoming a second campaign database. Phase references own operating instructions. Tests cover provenance, stale affiliation, guessed/published routes, namesakes, suppression, prior form and manual history, consent scope/revocation, exact and variant fingerprints, cadence boundaries, concurrent claims, uncertain acceptance, late replies, local-only/no-mail/no-scheduler and diagnostic/application isolation. Bundles include the helper/references through the existing allowlist. Installations change only through a separately authorized verified update workflow.
