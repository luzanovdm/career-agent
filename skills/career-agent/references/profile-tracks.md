# Profile and tracks

Read supplied career material and preserve its original meaning before adaptation. Ask for optional older versions, credentials, portfolio and secondary work only when useful. Do not require software-specific artifacts from other professions. Capture source observations with original locator, readable excerpt and actual observation time; an unreadable URL supplies no supporting excerpt.

Agent summaries, task briefs and generated drafts are navigation context, not new user confirmation or independent corroboration. Preserve the actual author and original source lineage. Reuse supported claims within their original scope without re-asking; a handoff does not renew the fact date, confirmation or disclosure permission. If underlying evidence is unavailable, retain indirect/provisional status. Never confirm a claim by citing a summary derived from that same claim or generated draft; resolve conflicts against the actual sources and attributed user corrections.

Use source.capture and claim.save. A claim records original assertion, interpreted meaning, source IDs, confirmation, disclosure, contradiction and original metric spans. For relevant strengths, interpreted meaning explains the task/decisions, actual personal contribution and supported team/system result; missing context stays unknown rather than a manufactured story. A meaningful qualitative contribution needs no invented number. Supplied wording can remain unconfirmed and useful in a provisional draft. Offer one compact batch of editable, source-grounded contribution interpretations: for example, making a change, coordinating its adoption or contributing to a team result, only where the evidence supports the option. Ask missing metric meaning, period, attribution and disclosure together, without suggesting new numbers. Reuse actual unknown/no metric/confidential/declined answers.

Read the confirmed claim_frontier when new strengths or corrections arrive; use paginated context --claim-scope bank to reconsider facts beyond old links, then update relevant track claim_ids. Use track.save for stable profession-neutral tracks: current field, adjacent field, greater responsibility, independent/project work where supported. Share claims between tracks; retain their distinct language, geography, compensation and employment policies. Each policy value distinguishes inherit, known, no_preference and unknown. Unknown override is not inheritance. Salary observations retain currency, gross/net and hour/month/year basis; do not infer exchange, tax or hours conversion. A narrower current task chooses a subset without deactivating other tracks. Present shared known conditions once and ask only material missing differences by track: location/work model, hours/contract, compensation with its own units and document language. Do not force monthly pay or the same conditions onto every track.

Use answer.save by exact meaning/scope/units with actual confirmation evidence and validity. Updating an exact answer preserves identity/history. Employer legal agreements never become broad reusable answers. An application phone choice is contact.phone.preference, scope purpose=application, units={}, value {disposition:use|omit|unknown,value:selected number|null}; keep actual user choice and do not infer a number. Private floor differs from an approved external compensation answer.

Use installed context and schema for the bounded command catalog, then schema INTENT for nested fields and examples. Save profile.update and the bounded records through command (or plan/apply); inspect receipt/revision and render --format profile. Completion is the saved source-backed claim bank, supported selected tracks and explicit material unknowns. Research starts only on an actual scoped choice; profile work does not start it.


Context is bounded and paginated. Check partial, pagination totals/remaining and next_cursor; retrieve exact claims/answers with --claim-id/--answer-id and exact source with --source-id. Respect omitted_by_scope and reusable_here. Do not broaden scoped answers merely because the current question is similar. Source observations must contain readable actual evidence; confirmation is attributable to its real supplied source and never implied by a failed URL fetch.
