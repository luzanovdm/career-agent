# Interview materials and requested practice

Start from the available invitation, readable role description, selected packet and supported profile. Do not require earlier application phases, a full packet or a mode questionnaire. Conversation/intake and interview-answer language are separate; reuse the role/track choice. A pasted invitation is useful evidence; a URL without readable content is not. New company/person research still requires the current scoped grant.

Default to saved private material: sourced role/company dossier, likely questions labeled as hypotheses, supported story outlines, positive truthful resume follow-ups, employer questions and actual logistics/unknowns. Use profession-appropriate concepts rather than assuming technical interviews. Separate confirmed company facts, source assertions, inference and unsupported questions. Link only actually observed readable concepts, preserving source/date; omit unverifiable links without blocking useful preparation.

Read original evidence before drafting each story. Preserve personal versus team attribution, numbers/units, career dates, qualitative strengths and disclosed limitations. Explain genuine gaps or career changes without inventing motives, hiding dates or belittling the applicant. Private growth/context notes never become external claims. For an unknown answer, retain a supported outline with an explicit missing piece; do not demand an exercise response as a prerequisite to saving materials.

Use installed context --task interview, existing selected case/packet IDs and packet.save with the interview/dossier slots. Preserve all other selected text slots and used claim/answer bindings on replacement. Interview-only work can use purpose interview and needs no fake resume, form or employer contact. Read back the saved selected bytes through deliver and show a concise navigation/result update. Preparation material saved is distinct from an actual interview invitation, scheduled event or passed assessment.

For a saved Q/A view, use the explicit career-agent.interview/1 JSON document in the interview slot; installed schema packet.save provides the bounded turn/source/term shape. Author each ordered question, answer outline or note with its actual status and source IDs. Link a concept only to its exact readable saved observation URL. Ordinary old text stays a document; the interface never guesses speakers. Opening Materials → Interview preparation reads the viewed packet/version and starts no practice.

Only an explicit practice/mock-interview request starts a drill. Ask one question at a time unless the user chooses another format; explain or stop when requested. Practice responses do not confirm new career facts. Explanation on demand answers the requested topic without an unsolicited quiz.

Calendar planning, connector access and reminders are conditional on the user's actual request, scoped source choice and available host tools. Store only necessary logistics/timezone/availability coverage; unknown or stale availability stays visible. Suggested slots/buffers are not reservations, messages or invitations. No scheduler/calendar client or automatic notification is included in the local runtime. Sending, booking and accepting terms need their own actual authorization.
