# Fixed local application portal

Use the bundled templates/portal/index.html, style.css and app.js as one versioned design. Keep the approved light sidebar, compact case list, toolbar, two-column packet editor and private notes panel; replace only campaign data. Do not generate a new dashboard or redesign it for each user. Default public labels are English; runtime data and document language follow the user's choices.

The agent runs career_portal.py STATE WORKSPACE BATCH_ID after actual packet preparation/readback and normal XLSX/CSV refresh. The export is a dated/revisioned snapshot, never the canonical event store. Existing exports and manual edits are never overwritten: use a new destination/version. Open OPEN.html after extracting the complete directory; no server, API key, package installation or author service is required. Keep the data/assets/document folders together. JSON is split into 100-row index chunks, with a file-safe script envelope for local browsers that restrict fetch. UI pages show at most 50 cases, cache at most six chunks/resources, and load packet/document bodies on selection. Search scans summary chunks progressively with cancellation and a visible progress indicator; it does not construct all rows/documents in the DOM. No full-data inline HTML or cross-origin proxy is needed.

Each case has a stable case/attempt identity, exact opportunity ID, observed sources, concerns, packet state and selected immutable artifacts. Company prospects are not open vacancies. Incomplete/blocked cases stay visibly incomplete. Copying text, opening a route or checking a browser status never sends anything or marks canonical delivery. No automatic email, account creation or agreement acceptance exists. Local notes/edited text are private unreviewed working copies and cannot inherit a resume's semantic approval.

Browser progress uses a workspace-specific namespace. Storage can be unavailable or behave differently for local files/browsers/moved folders: show the warning and offer export/import. The portable JSON contains user-reported progress, not provider proof; the agent must reconcile it explicitly before changing canonical state. Do not silently sync browser edits into sent statuses. Export before moving folders/changing browsers. Snapshots keep revision/hash/date, and refreshing requires the agent; no fake background freshness or monitoring. Downloads include only selected exact artifact bytes, deduplicated by hash. Private dossiers/notes must not be sent to employers. Binary versions are reused only if already approved; new per-case drafts remain Markdown.

Appearance uses the same layout in Light, Dark and System modes. System is the default and follows operating-system changes while selected; explicit choices persist locally per workspace. This is a view preference, not a campaign fact. Do not regenerate the design to change themes.

Saved interview_prep items appear in an on-demand messenger-style section with linked concepts, suggested answer outlines, evidence IDs, resume follow-ups, unknowns and candidate questions. Only recorded/checked concept URLs are linked. Opening this section never starts a mock interview or research.

Distribution compiles the three canonical template files into the data-only scripts/career_portal_assets.py module so existing v0.1.1 updaters can accept the bundle through their existing path allowlist. The exporter writes the same template bytes; compilation never generates a new design or includes candidate data. Source development reads the canonical templates directly.
