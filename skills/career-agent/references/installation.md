# Installed runtime and local application

The agent performs installation in the user's chosen private workspace and asks/reuses desired UI locale. English and Russian catalogs are built in; another language can be translated by the agent into the workspace customization catalog through locale.install. Conversation and document language remain separate. Never modify signed release assets for translation.

Use only the approved complete platform archive and its exact descriptor/archive digest. Host native hashing/archive tools verify before execution; reject absolute/traversing/duplicate/symlink entries and unknown top-level paths. Extract into private staging, then invoke that verified archive's bundled Python with -I -B bin/bootstrap.py ARCHIVE --workspace W --sha256 DIGEST --name DISPLAY_NAME --ui-locale LOCALE. This bootstrap is the only installed-copy exception. A supported host needs native execution/filesystem capability, not an already installed Python/Node. If safe extraction/runtime execution is unavailable, report the unsupported capability and use the portable handoff.

Bootstrap verifies every managed file, runtime provenance/platform and staged sqlite3/ssl self-check, promotes an immutable release and atomically switches active.json before installed initialization. Runtime-installed and workspace-initialized are separate journal states. Repeating the same archive is idempotent. Legacy data returns IMPORT_REQUIRED; no automatic migration occurs. Failed staging and customizations are retained. Platform manifests distinguish declared minima from tested evidence; untested targets are not a release certification.

After initialization invoke W/.career-agent/career only. app status/verify report installed identity; app rollback changes code only. Updates use the same explicit approved offline install boundary; stop the local server/cooperating writers and preserve dirty UI edits first. No global skill replacement, privileged install, startup-at-boot, firewall change or persistent credentials are introduced.

Before writes after an update, inspect free space and aggregate count/size of older Backups/r*-*.sqlite3 through available read-only filesystem tools; do not create a backup just to diagnose storage. Version1.0.0 could accumulate unbounded snapshots in any installation. Version1.0.1 bounds new Automatic checkpoints but does not reclaim old occupied space. If headroom is insufficient, hold writes and report it. Offer a dry-run list of exact proposed deletions and preserved verified recovery points; deleting older snapshots needs separate approval. Never remove portable/manual/migration archives automatically. If filesystem inspection is unavailable, state that limitation; runtime preflight still refuses unsafe writes.

ui open starts/reuses the matching workspace/release process and opens a one-use authenticated loopback URL. ui status/stop/restart use private current-user control, never a remembered PID/port alone. An old tab does not scan ports after restart. Secrets remain run-scoped; sessions/capabilities expire when the process stops. Closing chat does not stop the UI. The server performs no research or transmission.

Views are derived: render --format csv|xlsx|profile|snapshot. The React app edits the same SQLite database through bounded domain commands and receives durable CLI change invalidations. Dirty text is retained on disconnect/conflict. No browser campaign store, external fonts/CDNs or cloud translation dependency exists.
