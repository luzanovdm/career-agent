# Offline legacy importer

This maintenance-only path is excluded from every installed application archive. Run it against a separately verified disposable copy, never the live source directory as a destination. Source development may read legacy data privately for the explicitly authorized rehearsal; no personal content belongs in this checkout, screenshots, shared fixtures or publication assets.

```sh
python3 -B maintenance/import_legacy.py --source /private/restored-copy --destination /private/absent-import-candidate --state-sha256 EXACT_SOURCE_HASH --allow-partial
```

The CLI supervises only its own isolated Python child. A250ms current-user RSS observer enforces a4GiB budget, a30minute elapsed budget, and waits for the owned child on failure. Sampling is not an instantaneous kernel RSS ceiling. macOS uses fixed /bin/ps for that owned child, Linux uses /proc; unsupported observation fails closed. No arbitrary process or command is accepted. A failed budget cannot leave a just-completed report activatable. No root privileges, persistent credentials, network or global installation are used.

Hard ceilings are256MiB canonical JSON input,512MiB per original file,12GiB cumulative source bytes,200000 filesystem entries,1000000 logical records/256 groups,1MiB reference sidecars,12GiB compressed archive,2048 chunks,128MiB report, and8MiB default chunks. Limits may only be lowered; chunk/report sizes have a64KiB minimum to prevent metadata amplification. --max-state-mib defaults to256 and cannot raise the ceiling. Conservative free-space admission reserves twice inventoried bytes plus four state sizes and256MiB. Every read/hash rechecks bounded sizes and source stability. Record parsing uses bounded standard-library JSON; archive and report writing stream. Actual elapsed time, peak RSS, limits and supervision results are recorded.

Every inventoried original and symlink metadata is retained in a deterministic gzip/tar stream split into ordinary immutable object chunks. The raw203MB state does not bypass the clean runtime25MiB object/upload limit. A small manifest binds compressed-stream hash, chunks and original inventory. Archive verification reads every member back without extracting paths and compares exact file hashes and link metadata. An oversized historical material cannot masquerade as a normal selected PDF: its original survives in the archive, while unresolved material/reference semantics remain quarantined.

Registered materials and historical reference targets remain ordinary content-addressed material objects when within runtime bounds. Application reference discovery covers Applications/**/*.json and **/*.reference.json, with explicit statuses and resource-limit quarantine. Every logical original record remains in record_history; exact original bytes remain recoverable from the archive. Historical selected/sent pins and statuses are mapped without approving current content or guessing missing pins. Unknown semantics are individually quarantined; no records are silently discarded.

The destination starts with an in_progress, nonactivatable import report. Every failure preserves that disposition. Successful retention with --allow-partial is not strict acceptance: strict_pass/activation_allowed stay false while quarantine or integrity failures remain. Bootstrap enforces this gate. The original source remains authoritative. Rollback before activation means discarding the unactivated destination; later writes prohibit blind database replacement.

Fictional regressions cover26 reference shapes, large-source chunking/readback, bounded failure paths, owned-worker termination, historical pins/statuses and quarantine activation refusal. Actual rehearsal details must be evaluated separately; passing synthetic26-reference tests does not certify the real historical groups.


Normalization distinguishes operative data from audit history. Original achievement assertions, numeric anchors/metrics and supplied interpretation fields are mapped into the current claim bank with their supported/unknown/hypothesis/confidential statuses and exact fact/source links; this does not approve a new packet. Omitted metadata in later claim edits is preserved. Every change_history occurrence is read back by its physical retained row and hash and classified as read-only audit history, not current permission or task state. Unlinked historical scope, form responses and current profile/campaign/packet pointers remain explicit separate quarantine reasons; no admission flag is relaxed to hide a missing mapping.

### Read-only retained observation projection

`project_history.py` prepares the current typed projection of retained unlinked observations after offline import/reconciliation. It does not resolve role identity, create activities or change admission flags. Run it with the destination's verified installed Python and `-I -B`; preparation writes a new private JSON file, not the database. Review its exact source fingerprint, then use `--input FILE --apply --expected-source-fingerprint SHA256` to populate only the rebuildable `view_exports` cache through the installed repository owner. Apply checks the captured workspace, business revision and original physical-row hashes. A changed source requires preparation again. Keep original retained history authoritative. The runtime/React reader consumes the typed projection; it has no legacy-format interpreter. Rehearse and compare business-table hashes on a copy before applying an update to an existing workspace.
