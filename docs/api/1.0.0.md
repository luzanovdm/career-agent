# Career Agent 1.0 local API contract

Protocol `career-agent.local/1`. JSON UTF-8, snake_case fields. Business responses are `{workspace_id, revision, ...payload}` from one snapshot. Issues are `{code, message, record_id?, required_bytes?, free_bytes?}`. Errors: `{error:{code,message,issues:[]},revision?}`; 409 `REVISION_CONFLICT`, 422 invalid input, 503 busy; 507 `DISK_SPACE_LOW` preserves uncommitted state and reports required/free bytes in its typed issue. Backup retries revalidate complete SQLite bytes and the protected plan; no existing filename implies successful recovery. Never treat a response as saved unless `outcome` is `satisfied` or `partial` with a command receipt. No sending endpoint exists.

## Browser session

Launcher opens `http://127.0.0.1:PORT/#launch=ONE_USE_CAPABILITY`. Read/clear fragment immediately with history.replaceState. POST `/api/v1/session` JSON `{capability}` with exact Origin. Response `{csrf_token,protocol}` sets HttpOnly SameSite=Strict session cookie. Every private request uses credentials same-origin; mutations require `X-CSRF-Token`, exact Origin and application/json. Launch capability expires after 60 seconds; sessions end with process. No token persisted in browser storage. GET `/health` returns `{protocol,status}` only.

## Queries

GET `/api/v1/context`: `{workspace_id,revision,profile:{display_name,conversation_language},tracks:[{id,name,positioning,selected,language,policies}],preferences:{theme:'system'|'light'|'dark'},research:{status,scope,expires_at},counts:{cases,contacts},next_missing_input:[]}`.

GET `/api/v1/cases?limit=50&cursor=OPAQUE&view=board|table&column=qualify&track_id=ID&q=TEXT&closed=false`. `column` optional. Allowed columns `qualify`, `prepare`, `ready`, `waiting`, `response`, `closed`. Returns `{workspace_id,revision,items:[CaseSummary],next_cursor:null|string,counts:{total,columns:{qualify,prepare,ready,waiting,response,closed}},qualified_people:number}`. Count scope includes q/track/closed, excludes pagination and column. Cases count once across tracks. Max limit100; default50. Cursor is revision-bound; changed revision returns409 to refetch bounded active page. GET `/api/v1/contacts` supports limit/cursor/q/company_id; returns items `{id,name,company_id,affiliation,relevance,route:{kind,value}|null,qualified,issues:[]}` plus next_cursor and total.

CaseSummary: `{id,company_id,company,opportunity_id:null|string,title,kind:'vacancy'|'project'|'speculative',tracks:[{id,name,rationale}],route:'person'|'form'|'unknown',contact:null|{id,name,qualified},column,next_action,blockers:Issue[],selected_packet_id:null|string,selected_version_id:null|string,allowed_actions:Action[],version:number}`. Action `{intent,label,requires_input:boolean}`. Actions are real domain intents, never move-card. `packet.save` drafts -> prepare, actual current reviews -> ready; `activity.record` actual transmission/response -> waiting/response; `case.close` -> closed; `case.reopen` retains history. No client readiness calculation.

GET `/api/v1/cases/:id`: `{workspace_id,revision,case:CaseSummary,notes:string,packets:[{id,purpose,person_id,selected_version_id}],selection:null|SelectionProjection,history:[{id,kind,occurred_at,evidence,version_id}],interview:[{slot,text,artifact_id}],sources:[{id,locator,excerpt,observed_at,readable}]}`.

GET `/api/v1/packets/:id/selection`: SelectionProjection plus workspace_id/revision. Projection `{packet_id,version_id,case_id,person_id,purpose,slots:[{name,artifact_id,sha256,media_type,text:null|string,download_url}],assessment:{saved:true,prepared:boolean,qualified:boolean,issues:Issue[],unknowns:string[]},review:null|{id,findings,limitations},version:number}`. Private slots (`dossier`,`interview`,`notes`) are labeled; download never sends. GET `/api/v1/artifacts/:id/download` verified immutable attachment.

## Typed commands

POST `/api/v1/commands` `{request_id:string,expected_revision:number,intent:string,input:object}`. request_id is UUID or unique opaque string <=128. Same ID/same body returns original receipt even after revision advances; changed body409. Response `{workspace_id,revision,request_id,outcome:'satisfied'|'partial',saved_ids:[],selected_packet_ids:[],issues:[],external_actions:{performed:0}}`. GET `/api/v1/commands/:id` resolves lost response: committed receipt or404 `NOT_FOUND`; do not invent success or blind external retry. All mutations atomic. Errors retain local text. A stale expected_revision returns409 with current revision. No forced overwrite.

Initial UI command inputs (exact keys, optional marked ?):

- `preferences.set`: `{theme}`.
- `profile.update`: `{display_name,conversation_language}`.
- `track.save`: `{id?,name,positioning,selected,language,policies:{}}`.
- `case.note`: `{case_id,text}` (private note, no content-review invalidation).
- `case.close`: `{case_id,reason,evidence}`; `case.reopen`: `{case_id,reason}`.
- `packet.save`: `{packet_id,documents:[{slot,text}],used_claim_ids:[],review?:{findings,limitations,claim_spans:[],tone_findings,coverage:[]}}`. UI text edits OMIT review; create/select new draft, previous immutable version retained. Slots resume/message/dossier/answers/interview/notes. At least one document. Packet creation via CLI `packet.create` below.
- `packet.select`: `{packet_id,version_id}` (no automatic review renewal).
- `activity.record`: `{case_id,kind,occurred_at,evidence,packet_id?,version_id?,resolves_activity_id?}`. Kinds `sent`,`uncertain`,`not_sent`,`receipt`,`human_reply`,`interview`,`offer`,`rejection`,`bounce`,`withdrawal`,`referral_agreed`,`referral_performed`,`coverage`. For sent/uncertain require exact selected packet/version, evidence and occurrence. Uncertain actions require linked reconciliation before another transmission. Evidence is actual user report/provider observation, never generated by UI.
- `research.control`: `{status:'active'|'paused'|'revoked',scope:{track_ids:[],purpose:string},evidence,expires_at?:null|string}`. Active requires explicit recorded choice. No session expiry.

CLI/model capture operations are also typed, discoverable through `schema INTENT`: `source.capture`, `claim.save`, `answer.save`, `company.capture`, `contact.capture`, `case.capture`, `packet.create`, `batch.save`, `permission.record`. No arbitrary record put, SQL, file path or process input accepted over HTTP. POST `/api/v1/uploads` accepts bounded application/octet-stream (25MiB), CSRF+Origin, returns `{input_id,sha256,size}`; opaque staged inputs only, no file path.

## Changes / live state

GET `/api/v1/changes?after=0`: `{workspace_id,revision,changes:[{cursor,revision,kinds:[],ids:[],projection_keys:[]}],resync_required:boolean}`. Up to1000 changes; retention10,000. SSE GET `/api/v1/events?after=N` (or Last-Event-ID): `id: REV\nevent: change\ndata: JSON_CHANGE\n\n`; `event: resync` with `{revision}` for cursor gap/overflow. Heartbeat15s. Server polls SQLite250ms so CLI commits included. No held read transaction. On change refetch affected active pages+counts+detail, reject older response generations/revisions, keep dirty text and display conflict. Poll fallback2s visible; hidden pauses. Server restart requires trusted launcher session; no port scan.

POST `/api/v1/runtime/stop` JSON `{}` authenticated; returns `{status:'stopping'}`. No arbitrary process target.

SelectionProjection additionally includes used_claim_ids and answer_ids. Intent resumption amendment: captured revision is context, not global intent expiry. resolve-intent verifies the original descriptor digest, current same-workspace target/selected packet/version IDs and scoped research permission. Unrelated revision changes return current revision and context_refreshed=true. Changed selected materials/primary target return409 SELECTION_CONFLICT. Board read amendment: GET `/api/v1/board?limit=50&track_id=ID&q=TEXT&closed=false` returns one coherent snapshot `{workspace_id,revision,columns:{qualify:{items,next_cursor},prepare:{items,next_cursor},ready:{items,next_cursor},waiting:{items,next_cursor},response:{items,next_cursor},closed:{items,next_cursor}},counts:{total,columns:{...}},qualified_people}`. Installed CLI exposes corresponding context flags. No arbitrary table/SQL query exists.

Review coverage reuse: packet.save review may include `base_coverage_version_id` referencing a reviewed immutable base resume. The new review stores only the target coverage overlay, validates actual claim-span bindings and flags lost/changed base achievements; it does not duplicate the base audit array or rescan all unrelated claims for every target. ## Occurrence-scoped numeric review (1.0.4)

`packet.save.review` optionally accepts `entity_refs:[{text,source_id}]`, `entity_spans:[{slot,start,end,text,source_id}|{slot,start,end,text,company_id}]` and `answer_spans:[{answer_id,text}]`, all bounded to100 entries. Scripts automatically resolve canonical company name/domain identifiers; the agent declares source-backed identifier meaning once and scripts locate complete tokens in the exact saved documents. A raw source excerpt is not an instruction or an automatic quantity exemption. Sources must be readable and within the target/person/used-claim scope. Numeric-only identifiers and packet-wide number-leading/measurement-shaped entity_refs exceptions remain refused. An exact entity_spans source reference can disambiguate a unit-shaped past-employer/project name only with scoped naming evidence and independent claim support at that occurrence. Saved source evidence must establish a named entity (a naming assertion, named software compound, link label or matching namespace); a literal occurrence alone is insufficient. Unknown measurement suffixes retain their exact opaque identity across joined spelling, Unicode whitespace and bounded unit wrappers/punctuation instead of becoming unitless. Unrecognized adjacent content words are ambiguous candidates, not semantically understood units; grammatical prose followers and sentence boundaries are kept separate. Both unit-shaped source names and canonical company names require exact role binding and independently grounded claim support at that occurrence. Measurement markers outside the complete span cannot be hidden, even when its identifier already resembles a unit. This does not establish semantic entailment (for example employment versus cutting a dimension); actual factual review remains necessary. No user markup form is introduced.

Numeric permissions belong only to the exact mapped claim/answer range. Entity digits never authorize an equal unsupported count, duration or percentage elsewhere. Signed/decimal spans and measurement units remain significant. Claim support and metric-retention checks share one unit normalizer; recognized aliases are equivalent, while changed currencies, durations and unknown units are distinct. Issues include optional `slot,start,end,token,role,unit,offset_unit`; offsets use Unicode code points, not UTF-8 bytes or UTF-16 code units. Saved review `numeric_audit` is script-computed, immutable metadata containing bounded occurrences and source/entity version refs; it is returned by full selection reads and cannot be supplied as an approval flag.

Selection requires `numeric_audit.policy` to match the current numeric policy. Missing/older policies yield `REVIEW_STALE` with `reason:numeric_policy_changed`, `saved_policy` and `required_policy`; prepared/factual readiness and exact handoff are false until actual current review. Cached case/board/table projections include the numeric policy identity. No immutable text, prior review or transmitted activity is rewritten by this check.

Old review records and statuses are not rewritten or automatically approved. Re-review uses the existing packet.save transaction with unchanged text slots, creating a new immutable reviewed version while preserving document hashes, historical status and primary selection. Updating runtime alone does not re-review or rewrite existing versions.


## Evidence-led message review (1.0.3)

The existing typed packet facade remains the only writer. `context --claim-scope bank` reads the confirmed/disclosable/non-disputed bank with normal cursors. Scoped contexts also return `claim_frontier` (token, counts and up to five excerpts outside the old links). This is candidate evidence, not an automatic relevance classifier. No second fact store is introduced.

`schema review-context` and `schema handoff-check` describe bounded read-only operations. Invoke each with `--input FILE` (or stdin). `review-context` accepts `{packet_id,documents,used_claim_ids,answer_ids?}` and returns `binding`, actual external hashes, target/dependency scope, bank token and `approval:false`. It neither reviews meaning nor writes approval. The binder excludes the general workspace revision, private notes, UI preferences and research state. It includes material candidate-bank/source changes, scoped writing preferences, exact external content, selected target/person/purpose and relevant record versions. New confirmed bank facts require reconsideration even when outside old track/packet links. Projection invalidation covers selected editorial reviews consistently; unrelated revisions do not expire them.

`packet.save.review.editorial` is `{argument,decision:'approved'|'revise'|'pending',findings,binding}`. The factual `findings`/`claim_spans`/`coverage` and tone findings remain separate. Scripts validate scope/bytes/shape/declared state; they do not prove that an argument is useful, that a source is true or that the reviewer actually understood it. Nonempty fields, length, figures and lexical patterns are not prose-quality tests. Real model review and independent behavioral acceptance own those judgments.

Selections return `assessment.factual_pass`, `assessment.editorial_status` and `review_context`; full review projections expose the editorial argument/findings. Message readiness requires current approved editorial attestation plus existing factual/mechanical checks. Old saved factual reviews remain historical, with editorial `not_recorded`; their texts/reviews are never silently rewritten or auto-approved. Incomplete/failed/stale drafts stay saveable.

`handoff-check` accepts `{packet_id,version_id,documents,artifacts?,recipient?}`. Documents contain actual final external text; attachment references `{slot,artifact_id}` must resolve to exact selected verified artifacts. Private slots, missing/changed payload, changed selection/recipient, unready review and unresolved transmission outcomes block `ready`. It returns the checked content hashes, payload hash and `permission_granted:false`, with zero external actions. The host must use those exact checked bytes and valid separate authority. This application does not implement a sender and cannot technically prevent an agent from bypassing it with an unrelated external connector.

An observed send/uncertain event can include `message_sha256`. It remains factual evidence even when local readiness or pinned content mismatches; the receipt and stored activity carry `SENT_UNREVIEWED`/`SENT_PAYLOAD_MISMATCH` warnings. `case-history` exposes observed/pinned hashes and retained warnings, without changing old event bodies or fabricating a non-send. Existing uncertainty/reconciliation rules remain.
